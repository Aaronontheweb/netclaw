The concrete change

A user presses Enter and then Ctrl+Q. The client must resolve daemon admission before it closes the transport.

Admission means that the daemon journal stores the text input. It does not mean that the model finished a turn.

Pinned baseline client, abbreviated

SubmitAsync(text):
  if not ready or disconnected:
    pending.Enqueue(text)
    start ConnectUntilReadyAsync()
  else:
    await SendAsync(text)

Connected callback:
  start EnsureSessionAndFlushAsync()

ConnectUntilReadyAsync():
  connect; acquire setup gate; bind; flush

RequestAppShutdown():
  Shutdown()

Replacement client, schematic

Receive(Submit(text)):
  pending.Enqueue(text)
  advance the current behavior

Unattached + pending input:
  Become(Operating)
  bindTask.PipeTo(Self)

Attached + pending input:
  Become(Operating)
  sendTask.PipeTo(Self)

Receive(Close):
  reject later submissions
  continue admission until done or deadline
  reply ChatCloseReceipt; Become(Closed)

Host disposal:
  terminate the local ActorSystem

The proposed example omits transport guards, identity mapping, cancellation, and event publication. Those steps remain required.

One actor will replace both the client command loop and the view model lifecycle paths.

The daemon fix will make the successful text RPC response depend on the existing journal acknowledgment.

CLI actor → existing SignalR SendMessage method
Registry → validate attachment, authenticated identity, and ingress → gateway actor
Gateway → existing ChannelInput.AckTarget → real channel pipeline → LlmSessionActor
Session → persist InputAdmitted → existing CommandAck → successful hub response
CLI actor → mark admission confirmed → permit normal close

The shared acknowledgment type retains its other meanings. This contract applies to the text-only SignalR SendMessage route.

Behaviors and controls

BehaviorRequired action
IdleAccept queued requests. A fresh connected chat remains unbound until input arrives.
OperatingRun one connect, bind, text, or interaction operation. Pipe its result to the actor.
RetryingUse one keyed retry timer. Retain ordered requests and the selected session.
ClosedReject later requests and ignore late results. Host disposal stops the runtime.

Close is a control protocol across these four behaviors. One timer bounds all prior admission work.

Use ReceiveActor and Become(...). Use PipeTo(Self) for network completion messages.

Each behavior must register its close, transport-drop, cancellation, and stale-result handlers. A behavior change replaces the previous handlers.

The actor must remain able to process a close or drop while a network task waits.

Operation identities reject stale completions. They do not cancel transport side effects.

Do not start a replacement operation on the same transport until the earlier task completes or transport teardown confirms its end.

Cancellation alone is not that confirmation. A fake that ignores cancellation must exercise this rule.

Retain the existing retry budgets for explicit connect and background recovery. Consolidate their schedules under the actor.

Use IWithTimers for retry, RPC timeout, and close. Use the injected TimeProvider only when a UTC timestamp is required.

Use stable timer keys for retry, operation timeout, and close. Akka cancels replaced timers and filters their stale messages.

Interactive attachment failures use the established 1, 2, 5, and 10 second escalation. Successful readiness resets that counter.

Authentication failure remains a terminal error for the affected request. Do not silently retry it as a transient network failure.

UI and close

Retain an event pump that cannot block actor commands when a subscriber blocks. It has no connection or retry authority.

The event pump forwards immutable status and output. The view model uses its existing InvokeAsync boundary for UI changes.

Model output and usage retain their current observers across reconnect. Admission results do not overwrite model-turn state.

If TurnCompleted arrives before the hub response, the later response must not restore the Generating status.

Normal quit sends Close before Termina shutdown or host cancellation. A repeated quit does not start a second close.

Close returns a terminal result to the caller. The caller renders its receipt before UI disposal.

Confirmed inputs need no model-completion wait. At the deadline, queued unstarted inputs are unsent; an unresolved input RPC has unconfirmed delivery.

The two-second deadline covers all queued admission work. It is not two seconds for each input.

A final receipt must survive alternate-screen teardown. Write unresolved message status to the terminal after the TUI closes.

ChatViewModel stores the immutable result in ChatNavigationState. Program reads it after RunAsync disposes the host.

This seam preserves the init factory's lazy endpoint, exposure, and device-token read. Each uncertain input retains its original session.

After the deadline, do not start another bind or send. Cancel owned tasks and complete transport teardown.

Forced process termination cannot guarantee admission. This plan does not add a durable client outbox.

Failure results

Connection or attachment failure before an input RPC leaves the input safe to retry.

A confirmed daemon rejection ends that input attempt and produces a transcript notice.

An interrupted RPC produces delivery unconfirmed. The client must not automatically resend that input.

Caller cancellation before dispatch removes the queued request with zero RPCs. Cancellation after dispatch can leave delivery unconfirmed.

This intentionally removes the current ready-path automatic resend after an uncertain send failure.

Unexpected actor failure must end the client visibly. Supervision must not silently restart the actor and discard its local queue.

A zero-turn session can contain durable input or an approval wait. Do not delete it because its turn count is zero.

Bootcamp sources and design checks

The Petabridge lessons support the selected local FSM. These notes distinguish lesson guidance from this plan's application decisions.

Behavior and asynchronous work

Behavior Switching and Receive Timeouts explains that Become replaces the current message handlers.

It also describes ReceiveTimeout as a period without relevant activity. Activity resets that period.

For this client, every behavior must retain the control handlers it needs. The close deadline must stay fixed despite later events.

Actors and Async / Await distinguishes ReceiveAsync from PipeTo.

ReceiveAsync suspends other user messages until its task completes. PipeTo sends the task result back as a message.

For this client, connect, bind, and send use PipeTo so close and transport-drop commands remain available.

Capture task inputs before dispatch. Task continuations must not mutate actor state or read the actor's current Sender or Context.

Deferred input, timer lifetime, and message data

Sagas, Message Stashing, and IWithTimers explains how a stash preserves messages and their senders until a behavior can accept them.

The lesson also describes actor timers that cancel on actor stop or restart.

This client retains one explicit input queue because close must inspect each input's delivery outcome. A second stash must not duplicate that queue.

Close, transport-drop, and cancellation commands must execute promptly. They must not wait in a catch-all stash.

Use IWithTimers and TestScheduler for elapsed deadlines. Retain TimeProvider for UTC timestamps; it does not drive actor timers.

Effective Actor Messaging separates commands, events, queries, and acknowledgments. It requires immutable message data.

For this client, separate local acceptance, durable daemon admission, and model completion. Each result must name the boundary it confirms.

A record with a mutable list does not provide deep immutability. Copy or use immutable collections when a payload crosses the actor boundary.

Proof through actor messages and real host composition

Testing Actors with Akka.TestKit demonstrates isolated systems and assertions on actor replies.

Integration Testing with Akka.Hosting.TestKit adds a real host, dependency injection, and the actor registry.

For this client, assert observable outcomes through probes and controlled transport results. Retain the separate real journal and native terminal proof.
